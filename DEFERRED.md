# Отложенные дефекты

Правило Даниила от 28 сентября 2026: дефект любой тяжести можно перенести до финализации архитектурного рефакторинга, если установлены причина, устраняющее её изменение, владелец и проверка закрытия. Обычные технические шаги не требуют повторного согласования. Перенос разрешает продолжать рефакторинг, но не означает исправление, PASS проваленной проверки или безусловную приёмку этапа. Все D-001–D-007 открыты и обязательны для финальной приёмки и выпуска.

Реализация, developer tests, независимый Code QA и Functional QA — разные состояния. Source-only сверка 5 октября 2026 на `36264bb8ef6e1a603cc0c4a0cc7e32b412c12cb8` не является новым gate. Raw failures и frozen manifests сохранены. Исправленные дефекты кандидата10 остаются в текущих проверках. Недостающие функции после C–E и все исходные требования сохраняет [инвентаризация паритета](docs/parity-current.md); затем обязательны полный паритет, продуктовая приёмка и реальные интеграции. Не создавать временную совместимость со старым внутренним Go-контрактом ради промежуточного PASS, если новая архитектура его заменяет.

## D-001 — таймаут d096 при параллельном race-прогоне

**Статус / цель / владелец:** открыт; перенос явно разрешён Даниилом («d096 точно можно»). Только этот дефект исключён из блокеров перехода; исходный полный FAIL остаётся FAIL. C4, владение агентским выполнением/чтениями; основной агент.

Повторная загрузка/сериализация quote измерена, но её оптимизация не доказана достаточной причиной исправления. Compact domain-owned fingerprints/receipt metadata обязаны сохранять current authorization, history generation, catalog/order denied/omitted semantics и полную проверку при исполнении. Ранний candidate нарушал эти semantics после удаления истории/изменения catalog/order и отвергнут.

**Доказательства / пределы:** [исходная диагностика](qa.local/architecture-stage-b-repair8/runtime-d096-diagnosis/DIAGNOSIS.md), [D001 REPORT](qa.local/architecture-stage-c4-d001/REPORT.md), [MEASUREMENTS](qa.local/architecture-stage-c4-d001/MEASUREMENTS.md). Исправленное измерение `pg-20260928T190501173Z`: preparation 2 requests, execution 3; preparation bytes 277518 (escaped277510) → 96. Ранние 2→0 относятся к rejected candidate; timing не доказывает ускорение. Один original uninstrumented Linux race PASS `race-candidate-full-20260928T191625257Z` не закрывает дефект; REPORT сохраняет незелёный pinned lint/source-binding ограничения. [R79](docs/qa/r79-runtime-diagnostic-2026-09-30.md): 91 completion, 51 miss, max7.07s, FAIL, не race. Существующие budgets модели, Execute, транспорта, Go/сценария и стенда не увеличиваются.

**Закрытие:** исходный полный набор с полным результатом, current authorization, durable cursor/inbox и прежними assertions, race/параллельностью; ограниченное завершение в существующем enclosing scenario budget, общий composed final run и свежие affected Code/Functional QA. Latency измеряется отдельно. Ранний acknowledgement, narrow query QA, benchmark или один PASS не заменяют полные сценарии. Graceful restart остаётся не более пяти секунд без forced kill.

**Закрытие:** real-PG baseline с настоящим privileged read item1, successful multi-item и interrupted/new-instance resume без повторного эффекта/изменения original source.
