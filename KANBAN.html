Правила движения

Очередь → разработка → локальные проверки → независимый Code QA → последовательный мёрж → интеграционные проверки → независимый Functional QA → принято. Замечания возвращают задачу конкретному разработчику. Повторная неудача требует смены разработчика или пересмотра решения.

Два–три разработчика работают над недостающими возможностями; исправления параллельно. Один владелец общего стенда, без перестройки во время QA. Публикация и production отдельно разрешаются пользователем.
