# Administrative pass assignment

Built, not independently accepted. No production writes or shared stand changes.

Python `zns-chatbot/plugins/passes.py:1691` starts the global-administrator
assignment command. Its options include total price, custom type/comment,
creation from saved settings or an explicit name/role, balance exclusion and
capacity addition to a selected tier. The Go adapter uses `Service.AdminAssign`
and `POST /v1/passes/admin/assign`; it does not duplicate allocation rules.

The registration queue links each participant to an assignment editor. It offers
current/standard price, a free pass, inclusion/exclusion from role balance and
capacity addition to the current tier. The administrator applies the displayed
draft explicitly. Creation from saved profile has a distinct apply label.
Custom prices, types, comments, earlier eligible tiers and explicit creation
details use natural instructions through the registration skill. Opening this
editor never captures an unrelated next message.

The skill first reads `admin_target`, using an exact numeric Telegram ID from
current text/contact metadata, the authorized queue or the current editor. The
read returns an owner reference; `admin_assign` uses that reference and nullable
assignment options. It cannot supply actor, keys or versions. The host binds
actor/target/profile versions from the read and persists the command before
dispatch. Explicit legal names must occur in the current request. A model cannot
resolve guessed names to numeric identities or obtain an unrestricted user list.

`GET /v1/passes/events/{event}/admin/targets/{telegram_id}` requires global
booking-administrator membership. Payment-administrator rights are insufficient.
Its narrow DTO contains display name, booking, versions, profile role/readiness,
frozen status, eligibility and current tier. It returns no stored legal name or
passport. Reads use the assignment service's event-then-user lock order. Cached
administrative reads are reauthorized before reuse; revocation hides the result.

Manual callback actions are stored under the acting owner and menu revision.
Financial changes advance the target booking version, so an old editor cannot
silently replace a newer receipt. The service preserves or replaces payment
attempts according to its existing rules. Idempotency keys are generated by the
host, and retries do not repeat assignment or tier capacity changes. A current
read can display the same editor with `show` and `view=admin_target`.

Tests cover the actual API permission boundary and private DTO, English manual
free assignment, foreign callbacks and retry, Russian agent creation with price,
type and comment, changed profile versions, revoked rights, guessed identities,
and an unrelated question while a draft remains open. Unit schema validation,
real PostgreSQL tests, pinned lint and vet are required alongside independent
Telegram-like browser Functional QA.

This slice handles one explicit target per action, including a reciprocal
waitlist pair when the service treats it atomically. Python's multi-recipient
CLI loop is not implemented by this adapter. A future bounded explicit batch
contract is still required for full parity; this stage makes no bulk-assignment
claim.
