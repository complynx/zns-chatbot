## Required across all stages: buttons/forms, agent and mixed continuation

Every key user workflow must be possible through buttons, commands and forms
without a Loom/agent turn, through the agent, and through a mix of both. These
are equal supported paths. A user can start in either interface and continue in
the other without restarting or repeating completed work. Structured text fields
must also work without the agent, including entering a full name; natural-language
expectations remain an optional agent entry, not the only route to completion.

Apply this requirement to event selection; registration and profile completion;
solo/pair participation and partner changes; pass status and assignment requests;
payment evidence, partial payment and top-up; avatar upload/editing; orders and
meals; massage booking, changes and cancellation. Apply it to key ambassador and
event-admin workflows according to permissions and required confirmations.
Only supported business actions are exposed; this requirement does not invent
cancellation, refund or financial policies that have not been agreed.

Both interfaces use the same persisted business records, expectations, deadlines,
versions, operation receipts, permissions and event/module eligibility. Record
manual actions as agent context without an unsolicited agent turn. Render current
agent changes in the next menu/form read. A stale button or form must revalidate
current state and cannot repeat a completed effect or silently overwrite a newer
agent change. An unavailable Loom must not block the structured route; shared
IAM or database failures still follow their existing recovery rules.

For every key workflow, acceptance requires the complete structured path with
zero agent turns, the complete agent path, structured-to-agent continuation and
agent-to-structured continuation. Check a switch while an expectation is pending,
a concurrent/stale submission, and recovery after a bot restart or lost reply.
Use real Telegram and the owned real Loom stand for end-to-end acceptance; API,
mock-peer and command-only checks do not establish those paths. Record each path
separately as passed, failed or not yet accepted.
