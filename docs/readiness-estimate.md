# Текущая оценка готовности — 29 сентября 2026

**Функциональный перенос: около 92% реализовано / 78% подтверждено. Архитектура: примерно 75–82% выполнено / 15% принято. Остаток всей цели — 26–53 инженерных дней по 8 часов.** Это объём работы, не календарный срок AI-команды и не прогноз расходов API. Уверенность в сроках низкая. Production пока не готов.

Пересмотр учитывает исполняемые части C, локальные gates, независимые Code QA и проверенную промежуточную композицию. Код в изолированных кандидатах входит в реализацию, но не становится принятым до обязательного Functional QA и проверки общего состава. Число файлов, тестов и агентов не переводится в проценты.

Это экспертная оценка объёма кода, а не доля готовности к выпуску. Прежние D=5% и E=0% устарели; локальные проверки новых кандидатов не заменяют независимую приёмку.

## Остаток всей цели

| Работа | Инженерных дней по 8 часов |
| --- | ---: |
| Остаточные условия B и сверка перенесённых требований; без повторного учёта их реализации в C | 1–2 |
| C: оставшиеся координаторы/границы, host-policy и ledger projection, интеграция, исправления и оба QA | 5–10 |
| D: lifecycle, доставка, shutdown и проверки сбоев | 3–6 |
| E: runtime без импортера, единая сборка и зависимости | 2–3 |
| **Архитектура B–E с проверками** | **11–21** |
| Недостающие функции и общие исправления после C–E | 4–8 |
| Итоговый импорт/identity/reconciliation | 2–4 |
| Полная системная и реальная приёмка | 5–10 |
| Резерв на новые дефекты и повторные проверки | 4–10 |
| **Вся оставшаяся цель** | **26–53** |

До промежуточного архитектурного аудита оценка была 25–50. Явное закрытие остаточной host-policy, typed ledger projection и deferred assessment добавляет 1–3 дня: теперь 26–53. Это экспертная поправка, не замер. После execution/CAS проверок прежняя оценка составляла 55–60%. На 29 сентября с учётом реализации D/E она пересмотрена до 75–82%, принято 15%; аудиторский отчёт не является QA. Остаток пока не сокращён: итоговый FIFO, композиция и независимые проверки ещё могут потребовать существенных исправлений. Первоначальное снижение с27–53 объяснялось тем, что часть C уже реализована, B сводится к остаточным условиям. Работы по D–E, отсутствующим функциям, реальным интеграциям и резерв не сокращены. Перенесённые D-001–D-003 считаются в реализации C; повтор исходных сценариев входит в его QA, а не оплачивается второй полной строкой B.

**Календарный срок надёжно не оценён.** Разработка параллельна, но композиция, ограниченные ресурсы тестов и свежие QA имеют последовательные зависимости. Делить оценку на число агентов нельзя. Следующая переоценка — после общего замороженного C и его двух QA.

## Доказательства и ограничения

- C1: bounded registration reads и zero-result HTTP contracts, host/history admission до marshal прошли scoped gates и fresh Code QA; интегрированы. Общий native1568 прошёл, integration скомпилирован; это не полный PG/FQA.
- C2: authorized status/provenance и история1000 admissions прошли scoped PG; execution coordinator прошёл actualBot metadatafailure/retry без model/duplicates. Typed/CAS composition компилируется. Public selection/resume/opaque witness, final lint/review и Functional QA ещё открыты.
- C3: deferred assessment и cancellation/accounting прошли focused PG и fresh scoped Code QA, интегрированы. Общая stage Functional QA остаётся открытой.
- C4: C4a прошёл gates/Code QA; C4b — проверки с отдельным замечанием по зависимости. Transport repair прошёл gates/Code QA и объединён с C5; production dependency closure agenthost больше не содержит API/Telegram/bot. C4c прошёл native/vet в отдельном составе; итоговые gates и FQA впереди.
- C5: account и workflow прошли scoped gates и свежие независимые Code QA, объединены в рабочем C. Совместные native agent/agenthost/appclient/bot прошли, workflow компилируется. Это промежуточный состав, не финальная приёмка.
- B: полные автоматические gates кандидата10 и профильные кандидата11 сохранены; author-consent/source-privacy FQA прошли в объявленном объёме. Незакрытые recovery/replay условия остаются в [DEFERRED.md](../DEFERRED.md).
- Штатная импортная репетиция schema074: 7 apply/7 replay/5 reconcile,45 проверок и161 сохранённый fingerprint после удаления временного импортера. Это не доказательство готовности всего импортированного runtime.

Главная неопределённость теперь — взаимодействие частей C после объединения, полный регистрационный coordinator, D lifecycle и финальные внешние интеграции. Локальные тесты обнаруживают как реальные дефекты, так и ошибки fixtures; пропущенный или неуспешный сценарий не считается пройденным.

100% требует всего согласованного scope, мигратора и его удаления, принятых архитектурных этапов, обоих независимых QA и финальных разрешённых интеграций. Функциональные и архитектурные проценты не усредняются: общих сопоставимых весов программы нет. Локальные коммиты/ветки разрешены; push и production deployment требуют отдельного разрешения.
