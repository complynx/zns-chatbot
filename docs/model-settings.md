# Model settings

The host owns each request's effective model selection. Model-generated plans
cannot override the transport selection through their input or output fields.
Authorized settings operations change persisted choices for subsequent requests.
The default remains `gpt-6-luna`, with provider-default reasoning when no explicit
choice exists. The finite catalog supports Luna low through max, and Sol/Astra
low through ultra. No arbitrary model names or CLI configuration are accepted.
Provider availability still depends on the operator's provider account.

## Permissions

`core.pass_booking_admins` is the existing canonical global administrator map.
Its members have all settings permissions and can grant each permission separately.
Event/payment administrators and ordinary users get none implicitly.

| Permission | Scope | Telegram command |
| --- | --- | --- |
| own | Caller dialogue only | `/model [model effort \| reset]` |
| others | Another user's dialogue, never self | `/model_user <owner> [model effort \| reset]` |
| global | Default for dialogues without an override | `/model_default [model effort \| reset]` |

Only global administrators can use `/model_access <owner> <own\|others\|global> <grant\|revoke>`.
The owner argument is the internal user ID. Authorization is checked by the API
on every read/change, including retries. Menus are built from current permissions.
Changing another dialogue's choice does not give that user permission to change it.

Authenticated routes: GET/POST `/v1/model-settings`, `/v1/model-settings/users/{owner}`,
`/v1/model-settings/default`; POST `/v1/model-settings/grants`.
GET `/v1/model-settings/effective` returns only the caller's effective selection.
Changes require `operation_key` and current `version`; reset uses empty model/effort.
Conflicting key reuse and stale versions return 409. ACL checks precede replay.

## Inheritance and revocation

An active explicit override takes precedence over the global default. Reset clears
that override and inherits the current default. Changing the global default does
not overwrite explicit overrides. Resetting the global default restores the deployment default.
An own-authored selection stops taking effect when own permission is revoked.
The selection remains stored and can become active if permission is restored.
Previously authorized assignments to others and global defaults persist after the
author's permission is revoked; revocation prevents new writes. These assignments
remain effective even when the target lacks own permission. Author and authority
are retained in the settings row; operation records preserve committed changes.

The bot reads one authenticated effective snapshot before the logical planning
loop. Skills, subsequent context reads, and planning use this same snapshot.
Changes during a request apply next request. OpenAI sends model plus reasoning
in the Responses payload; Codex uses bounded argument values without global env
changes; Remote transports selection in validated headers over the existing
private host-to-model network. Public model input has no selection fields.
Auxiliary background knowledge assessment/history summary use deployment defaults,
not the interactive dialogue override. No provider calls are made to validate choices.

## Script bindings under acceptance

The isolated `qa.local/model-tools` candidate adds the following bindings. They
are not yet integrated or functionally accepted; see PROGRESS for current status.

- `models.effective()` reads the authenticated caller's effective selection.
- `models.own.get()` / `.set({model, effort})` require the own capability.
- `models.others.get({owner})` / `.set({owner, model, effort})` require others.
  The target must be another user, never self or the global scope.
- `models.global.get()` / `.set({model, effort})` require global.
- `models.grants.set({owner, capability, enabled})` requires current superadmin.
  Capability is only own, others or global. This does not grant superadmin.

Getters include the supported catalog. Setters require both strings; empty model
and effort reset inheritance. The host supplies current version and operation key.
List/help omit unauthorized bindings; execution and the domain transaction check
current access. A script cannot change the model already selected for its current
logical request. Existing manual commands and inheritance rules remain the same.

For a local synthetic provider, set `model.provider: remote` and `model.url` to
its private base URL. POST `/plan` receives the normal JSON agent input and returns
a bare JSON Plan, without a wrapper. Headers `X-Zns-Model` and
`X-Zns-Reasoning-Effort` carry the host-selected values. A fixture provider instead
uses the protocol in [model-fixtures.md](model-fixtures.md); do not infer model
transport selection solely from text generated by a fixture.

Official API reasoning reference: https://developers.openai.com/api/docs/guides/reasoning
