# Manual-First Functional Acceptance

Daniel authorized this execution choice on 6 October 2026. It supplements the
existing coordination process; it does not replace any original requirement.

QA classifies each scenario as manual, hybrid or automated. A separate fresh
reviewer accepts the classification. Use the actual Telegram-like UI for
conversational quality, locale/card freshness and ordinary actor navigation.
Do not author a separate assertion suite for each visible transition.

Daniel clarified language acceptance on 8 October 2026: changing the locale does
not require retranslating earlier messages or cards, especially unsaved messages.
Verify the persisted choice and subsequent replies, notices and usable actions in
the selected locale. Historical text in its previous language is not a defect.
Old callbacks must still respect current permissions and complete without blocking
later input. Keep question/answer language separate from the stored UI locale.
Apply this clarification to new acceptance runs; do not rewrite frozen verdicts.

Hybrid scenarios retain exact released replay, fault, clock, byte and durable
state observations. UI alone cannot prove these boundaries. Existing mandatory
automated gates, full/final suites, original budgets and both independent stage
QA gates remain required. A confirmed product defect receives its necessary
focused regression coverage.

Record complete scenario evidence, including EN/RU, applicable input and authority
cells, current immutable access binding and limitations. Unrun or blocked is not
PASS. Classification is an execution choice, not acceptance or reduced scope.

Before arming the scenario clock, qualify the actual observer entry against the
released environment. Capture one allowed nonbusiness readback and check its
behavioral meaning, not an assumed JSON representation. Verify that the action
connection can reach its own declared pages. Keep one connection and explicit
page objects for a stateful UI flow; do not infer page ownership across separate
connections from a running browser process. Retain clipped private exceptions
before closing the observer. These are focused QA instrument checks, not a new
runner framework or another product Code QA campaign.

Qualify the complete consuming path against existing factual samples in one
batch: actual readback types, per-role image and required health, actor mappings,
producer/consumer paths and legitimate file authorization. Workers need not use
the app image or the same health contract. Bind observations to the qualified
role-specific release. An empty field's representation is not a capability.

An ordinary observer error before input is not a product failure. QA may use a
corrected immutable instrument or a direct manual path within the admitted
resources and original clocks. Verify real accepted input, completed effects,
current permissions and fresh-session state. Finish one correlated action before
moving to the next actor, locale or card. Do not repair product state to satisfy
the observer. Product, SQL, lifecycle and security changes retain their affected
independent review and authorization boundaries.

The outcome owner prepares the complete existing-script launch sequence before
arming it. Each step consumes its predecessor's actual result; do not omit
browser prearm or retirement ownership when invoking a starter. After repeated
operator failures, transfer the whole outcome to another developer and retain
the first owner only for bounded cleanup and recipe support. Reuse unchanged
reviewed components instead of restarting a source-review campaign.

Before acquiring resources, verify that the assigned QA owner is active and its
sole writable evidence directory physically exists with the declared inputs.
A queued message to a completed agent is not preparation or acceptance. Resume
that owner explicitly and coordinate directly; ROOT need not approve each step.
If another admitted runtime changes the required custody binding, obtain its
actual declaration or wait for its bounded release. Do not launch another
preparation campaign merely to chase a moving dependency.

Current QA-owned classification and its independent review are linked from
management.local/PROGRESS.html. Do not edit an immutable acceptance packet
to accommodate a later process change; use a reviewed successor when necessary.
