## Evidence and assessment

The reviewed public callers propagate these errors without replacing their database or serialization identity. `core.DatabaseOperationError` sanitizes driver diagnostics and retains cancellation, deadline, and NoRows behavior.
- Expected absence is still handled before normalization where it maps to missing/forbidden, an empty causal record, version zero, or an absent receipt. Domain conflicts, causal validation failures, and explicit JSON decoding/encoding errors remain outside SQL normalization.
- Terminal replay now marshals the receipt before the SQL update. This separates encoding failure from SQL failure while retaining the same JSON result and actor/key selection.
- Authorization checks, origin/reader validity distinction, revocation writes, lock order, and submission consent checks are unchanged. Receipt, audit, mutation, and causal writes remain inside their existing transactions; failures return before commit and retain deferred rollback.
- New scripted tests exercise named SQL fault sites with transport, PostgreSQL statement, serialization, and cancellation errors; they assert sanitization and that the intended SQL site was reached. Separate cases check absence, domain rejection, corrupt JSON, and deadline preservation. Pool tests use a bounded injected dial failure rather than an external service.
- The integration test closes the connection before fact insertion, receipt insertion, or commit; its assertions check rollback of fact/receipt/audit, recovery with the same operation key, and replay without duplicate effects. Each subtest obtains its own database fixture. Its commit case covers failure before COMMIT is sent, not an ambiguous acknowledgement after a successful commit.
- No dependency additions, new suppressions, or transaction restructuring occur in the assigned patch. The changes use the existing core helper and focused tests.
