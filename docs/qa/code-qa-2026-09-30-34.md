## Evidence

- `platform/internal/api/database_error.go:9` emits only the fixed provenance bit after positive `core.IsDatabaseFailure`. General, knowledge and profile responders preserve their existing public status/ProblemError JSON. General SQL failures no longer log driver diagnostics. Provisioning marks SQL provenance before retaining its existing 503/409/400 mapping.
- `platform/internal/appclient/client.go:137` bounds the complete error body, rejects malformed/trailing/oversized or missing-code JSON, copies the actual HTTP status, and wraps the sanitized ProblemError only for HTTP status >=400 with the exact marker `1`. The wrapper preserves errors.As and public JSON through core.databaseFailureError. All six scoped binary/snapshot readers use the same decoder; JSON and provisioning calls use it through requestAuthorizedLimit.
- All reviewed remote requests use configured Base endpoints and authenticated credentials. Shared boundedHTTPClient overrides redirect handling with ErrUseLastResponse, including caller-supplied clients. This prevents redirected credentials/responses from acquiring Core authority. No new arbitrary response URL is introduced. Supporting identity.Zitadel.post parses provider responses separately and does not inspect the Core SQL header; broker errors do not enter this decoder.
- SQL-origin tagging in identityprovision wraps only DB Begin, QueryRow/Scan, Exec and Commit returns. Existing expected no-row branches, provider calls and conflict decisions remain in place. Supporting core.DatabaseOperationError preserves nil, pgx.ErrNoRows and context cancellation/deadline errors. Transaction ordering is unchanged: immutable identity reservation commits before the provider/binding transaction; later rollback retains the reservation.
- `platform/internal/api/database_error_internal_test.go` covers raw SQL, marked public errors, provider and domain errors for three responders, asserting status, public JSON, marker and diagnostic secrecy. Provisioning tests distinguish raw SQL from provider failure on the authenticated endpoint.
- `platform/internal/appclient/database_protocol_internal_test.go` exercises JSON, exports, snapshots, proofs and provisioning readers with positive SQL markers, generic 500, provider 503, malformed/empty/trailing bodies, unrecognized marker and success; positive cases verify errors.As status. Its transport test checks negative classification and sanitized error text. Supporting binary redirect isolation test asserts that the redirect destination receives no calls.
- `platform/integration/identity_onboarding_sql_test.go:28` installs an actual PostgreSQL trigger raising SQLSTATE 40001 on core.users. Its fixture uses a real identityprovision.Service backed by PostgreSQL behind authenticated httptest HTTP. The observation hook returns the actual Host.ProvisionTelegram result unchanged. Supporting runInboxDatabaseFailure requires Bot.Run to return ErrDatabase while its timeout context remains active. The test checks 503 plus SQL provenance, both retained inbox rows, an unready reserved identity, recovery after trigger removal, exact owner/subject reuse and one provider creation. The provider is synthetic; the SQL failure and HTTP classification are not mocked to the desired result.
- No new dependency, transaction expansion or suppression was introduced by the scoped changes. The shared decoder removes duplicated error parsing without adding a separate abstraction hierarchy.
