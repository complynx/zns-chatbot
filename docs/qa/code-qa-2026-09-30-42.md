## Correctness (checked by reading the code)
- **The change is limited to the one Exec call.** At `write.go:50-52`, only an error from `tx.Exec` now goes through `core.DatabaseOperationError`. The row-count check at lines 53-55 and the invalid-field check at lines 37-38 (before any SQL runs) are unchanged. There is no shared or global wrapping.
- **What `core.DatabaseOperationError` does** (`core/database_error.go:17-28`):
  - `nil` and `pgx.ErrNoRows` come back unchanged. `Exec` doesn't normally return `ErrNoRows`, so that path doesn't apply here.
  - Any error that contains `context.Canceled` or `context.DeadlineExceeded` comes back as the bare sentinel error. Wrapped driver text is dropped, which is good for privacy.
  - Everything else, including an untyped `io.EOF`, becomes the fixed `ErrDatabase` ("database unavailable"). The driver's error is not kept inside it, so its message, details and SQLSTATE cannot leak.
- **Success, missing-row and validation results are unchanged.** `broadcast_profile_missing` and `invalid_broadcast_profile_field` are still plain `errors.New` values. `IsDatabaseFailure` correctly returns false for them.
- **Dependencies:** production code only adds the internal `core` import. The test also uses `pgconn` (part of pgx/v5, already required) and testify. There are no new modules and no lint suppressions.
- **Transactions and locking:** unchanged. The statement, its parameters and `ON CONFLICT` behaviour are identical, and after a failure the caller still owns rollback, as before.

## Findings
1. **Low (uncertain, not a confirmed defect): the SQLSTATE is no longer available to callers** (`write.go:51`). If any caller up the stack retries on `*pgconn.PgError` codes, such as serialization failure `40001` or deadlock `40P01`, that retry would stop working for this write. I couldn't search for callers, so this is unverified. For this statement, `ON CONFLICT` already handles unique violations, so no SQL error code is an expected outcome locally.
2. **Low: the timeout case isn't tested** (`database_error_test.go`). `context.DeadlineExceeded` has no test.
3. **Low: the cancellation test is weaker than it could be** (`database_error_test.go:51-54`). It passes a bare `context.Canceled`, so it doesn't show that a wrapped cancellation carrying driver text comes back clean. It also doesn't check `tx.calls` or the exact error text.
4. **Low: the tests only prove sanitising for untyped errors** (`database_error_test.go:31-35`). `EqualError(err, core.ErrDatabase.Error())` does meaningfully show that "EOF" doesn't appear. But no test uses a `*pgconn.PgError` with sensitive message or detail text, so sanitising of typed PostgreSQL errors isn't shown. The helper code does handle it correctly.
5. **Info: the test style could be clearer.**
   - Several scenarios share one test function with no subtests, so a failure is harder to pinpoint.
   - Line 48 reuses the `tx` from the invalid-field case. That works, and it proves validation made no SQL call, but it makes the test harder to read.
   - The embedded nil `pgx.Tx` would panic if the code ever called another method. That's acceptable here.
   - The `Telegram` function isn't called in tests, but it goes through the same `write` path.
