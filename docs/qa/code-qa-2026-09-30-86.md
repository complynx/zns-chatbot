## Findings

### P1 — pass rendering can consume a marked SQL failure and complete follow-up

Location: `platform/internal/bot/pass_menu.go:203-207`, reached from the scoped `platform/internal/bot/pass_notification_views.go:18`.

`passMenuFailure` returns nil for every `ProblemError` below HTTP 500 without first checking `core.IsDatabaseFailure`. `renderCurrentPassMenu` uses this helper at `pass_menu_render.go:85` after `r.build` fails, then fetches events and continues rendering. For an open home view, a `PassBooking` response carrying HTTP 403 plus the database-failure marker therefore becomes a successful events fallback if subsequent calls succeed. The same helper is used at `pass_menu_render.go:279` for `PassQueue`, where a marked denial can disappear without even entering the fallback. `deliverPassNotification` subsequently sees nil, passes its SQL guard, and invokes `CompletePassNotificationFollowup` with `Done: true` (`pass_notifications.go:93-101`). This violates the explicit marked-domain-status requirement and allows rendering writes after a positive SQL failure.

Fix: preserve database failures before domain-status handling in `passMenuFailure`. Add a targeted open-pass-view notification follow-up test with a marked 403 from a rendering API, healthy later responses, and assertions that no fallback/render writes or follow-up completion occur. Keep the unmarked domain-denial fallback control.

### P1 — marked stale-source failures can trigger redaction instead of propagation

Location: `platform/internal/bot/pass_menu_redaction.go:18-22`, reached through the same scoped pass refresh.

`stalePassMenuSource` matches only the public problem code. In `RenderPassMenu` (`pass_menu_render.go:58-59`), a saved source plus a marked database error with code `source_stale`, `pass_source_stale`, or `historyStale` invokes `redactPassMenu`. That starts a transaction and changes the saved view (`pass_menu_redaction.go:29-36`) after the SQL failure; if redaction succeeds, the notification follow-up can also be completed. This branch remains unsafe even after fixing `passMenuFailure`, because source checking returns before the build/fallback helper.

Fix: exclude positive database failures from stale-source classification. Cover a marked stale-source response at `CheckBotDeliverySource`, preserving the saved source/view and returning the SQL classification without completion; retain ordinary unmarked source-revocation redaction.
