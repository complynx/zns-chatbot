## Evidence

- `database_error.go:17-24` turns untyped errors from a known SQL operation into the closed sentinel, preserving nil, missing rows and context cancellation/deadline. `DatabaseFailure` preserves the sanitized public error chain and JSON representation while carrying private provenance. `IsDatabaseFailure` does not infer provenance from text, HTTP status, EOF or generic network errors.
- `registrationingress/ingress.go:48-93` marks errors at concrete lock, insert and scan calls. Identity and native-payload validation happens before SQL. Conflict behavior remains the generated `ON CONFLICT DO NOTHING` or explicit application upsert. `TelegramPosition` retains `pgx.ErrNoRows`; its caller in `passbooking/admission.go:168-176` still maps absence to forbidden. No expected SQLSTATE branch is erased in these methods.
- `registrationnative/native.go:30-44,94-119` distinguishes SQL query failures from decode/validation outcomes. `Check` handles no-row as stale before marking other SQL failures, and its caller still applies the source/identity fence before using the result. Native binding comparison, revision and command checks are unchanged.
- `bot/inbox.go:18-49` keeps ingress, every inbox row and the received cursor in one transaction; failures return the original offset. Sorting uses a clone, so intake does not modify the supplied slice. `finishUpdate:78-94` keeps processed cursor advancement and inbox removal atomic. `drainInbox:53-75` preserves existing terminal-plan handling and retains an update on other errors.
- `bot/registration_ingress.go:43-63` marks Begin/Commit SQL failures; saved ingress errors propagate with their provenance. `bot/bot.go:609-615,632-642` stops on a classified SQL fault before reconciliation or the next polling request and returns the closed sentinel. Cancellation exits cleanly, matching the existing deferred `creditCutoverRunResult` contract. Other poll failures remain retryable; invalid cutover diagnostics remain terminal.
- Core unit tests cover typed PostgreSQL failure, wrapped failure, a source-marked untyped EOF, no-row/cancellation, arbitrary HTTP/problem errors, provider network/EOF errors, JSON and public error-chain behavior. Ingress tests inject EOF at both lock and insert. Native tests inject query EOF and reject invalid input before SQL.
- Integration tests use real PostgreSQL trigger failures rather than a fabricated application error. The batch test checks one attempted failure, rollback and restart; the completion test checks an already committed workflow and no duplicated model/audit effects on replay. The registration test checks no saved ingress/inbox/cursor or model call before a fresh Run succeeds. The timeout helper distinguishes fault exit from cancellation. Existing cancellation/restart coverage verifies durable inbox replay without upstream updates.
- No new suppressions, dependencies, authority shortcuts, or transaction restructuring were found in this scope.
