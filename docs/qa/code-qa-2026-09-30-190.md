## Finding

[P2] Limit deleted-payment redaction selection to the unavailable/deleted case, preserving pagination retirement.

Location: final/platform/internal/bot/delivery_cards.go:167-169; final/platform/internal/bot/payment_card_redaction.go:22-23.

The new branch interprets every botRetiredCardKey=true payment card as payment_redaction. The flag also covers payment instructions for an existing order that moves off the selected orders page. Current dependencies prove this reachable: order_paging.go:139-146 marks payment cards for every existing order as available before slicing the page; orders.go:182-203 refreshes only selected-page orders and then retires inactive cards; order_cards.go:130-157 sets the retired flag for both unavailable and off-page cases, explicitly choosing OrderOffPage when available=true. The candidate replaces that supplied off-page payload during dispatch with fixed PaymentUnavailable text. Thus navigating away from a live order changes its existing payment instructions to a deleted/unavailable notice even though the order and payment context remain valid. It also persists a view hash for different text than the enqueue-side retirement selected.

Keep source-free deleted-context retirement, but distinguish that retirement reason from ordinary off-page retirement before selecting its family, or reconstruct the correct bounded retirement notice from an explicit validated reason. Add a focused pagination case with an opened payment message for an existing order, move to another page, and verify the preserved off-page notice rather than PaymentUnavailable. This is independent of the required successful EN/RU deleted-order cases.
