## Blocking finding

[P1] final/platform/internal/agenthost/knowledge_context.go:127-137, with platform/internal/core/database_error.go:90-96: joined cancellation hides concrete SQL failure. Preserve positive statement/connection provenance before the non-SQL cancellation classification, and add the missing combined driver/cancellation cases.

`core.IsDatabaseFailure` recognizes ErrDatabase first, then returns false when any joined cause matches context.Canceled or context.DeadlineExceeded, before checking PgError/ConnectError. Consequently a live request with `errors.Join(denial, context.Canceled, &pgconn.PgError{Code: "40001", Message: "private SQL"})` follows the sanitizer's cancellation branch and returns the original joined error. This loses database/serialization classification and returns private driver diagnostics. With an already canceled request, the earlier ctx.Err() branch returns cancellation and still loses positive SQL provenance. A PgError alone or ErrDatabase joined with cancellation takes the intended sanitized route; the defect is the combined concrete-driver plus cancellation case. The analogous non-cancellation ConnectError joined with an independent cancellation is missed as well.

The new table covers concrete driver + denial and explicit marker + cancellation separately. It never combines a concrete driver with cancellation/deadline, so its assertions cannot detect this gap. Actual connection errors wrapping caller cancellation need to retain the existing true-caller-cancellation contract; distinguish those from a concrete SQL statement failure or independent joined positive connection failure, rather than treating every cancellation-containing error identically.
