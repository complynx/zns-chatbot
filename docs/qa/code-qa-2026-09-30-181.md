1. **[P2] Unencodable nonmatching text changes the upstream outcome.** `delayed_edit.py:194–197` hashes `payload["text"].encode()` before deciding whether the request matches the armed text. With the stand armed for chat 101/message 7 and ordinary text, an unrelated edit body `{"chat_id":101,"message_id":7,"text":"\ud800"}` passes `eligible` but Python UTF-8 encoding raises `UnicodeEncodeError`. The outer exception handler returns synthetic 502 without forwarding those bytes. The current fake decodes through Go `encoding/json`, which replaces an unpaired surrogate with U+FFFD, then processes the edit normally (`platform/internal/api/api.go:36`, `platform/internal/sandbox/fake.go:233`, `platform/internal/sandbox/delivery_format.go:32`; local Go `src/encoding/json/decode.go:99–102` documents the replacement). Thus this bypasses the provider's actual success or error body even though it is not the armed text. Treat text that cannot be encoded for matching as ineligible, preserve its original body for upstream, and add a focused armed/nonmatching-surrogate pass-through test. This is source-derived, not an executed reproduction.
