## Finding

The added source check handles a source already stale when `renderBotCard` starts. A source can instead become stale after this check and after the capture context is installed. For example, an existing derived card is being refreshed, both early source checks pass, and history is deleted while `renderCurrentPassMenu` builds the menu through an API call. `storePassMenu` then rejects the revoked source. `RenderPassMenu` calls `redactPassMenu` in the capture context. The tombstone and button deletion commit, but `renderRedactedPassMenu` calls `queueBotCard`, which passes the redaction to the active capture. That capture has family `passes`, so it silently ignores family `pass_redaction`. The render returns without a captured card; the original intent is cancelled, and no edit-only cleanup intent was stored. The previously visible derived body and keyboard stay on the original Telegram card until another external render happens.

The new `retireStalePassCard` call is outside capture, but is only reached by the early check. It does not cover this later branch. Ensure retirement detected during reconstruction also queues its exact edit-only effect outside capture before terminal cancellation. Preserve the revision/source checks and database-failure retry behavior. Add a focused existing-card refresh test that revokes history or a source grant during menu construction, after the new preflight succeeds, then asserts tombstone/source equality, deleted buttons, invalidated history, cancellation of the old intent, and actual edit-only retirement of the original message without a new send.
