## Evidence

- `saved_plan_recovery.go:168-186`: authenticated `KnowledgeReceipt` lookup precedes the completion read. Completed turns bypass `FinalizeCommand`; missing markers retain attachment recovery. Query and JSON failures return errors rather than treating the turn as unfinished.
- `saved_plan_recovery.go:192-215`: the durable reply is scoped to owner, update and reply kind. The lookup does not use a global/latest knowledge reply as its completion marker.
- `knowledge_receipt_notice.go:48-72`: completed pending-filter Suggest receipts return their recorded notice with `handled=true`; assessed and deferred notices are not inferred from the stale operation proposal state. Redacted receipts cannot enter this branch and use the unavailable catalog notice path.
- `knowledge_execute.go:44-73`, `interaction/knowledge_coordinator.go:64-71`, and `order_agent.go:47-76`: ordinary command execution attaches original sources and completes or defers assessment before the durable knowledge reply is written. Its text is produced through catalog IDs and the command result is marked trusted by `bot.go:328`; this path does not promote stored proposal bodies to trusted reply text.
- `knowledge/command_receipt.go` and `knowledge/causal_replay.go`: recovery still crosses current command authorization, original derivation/output checks, history generation and private deletion verification. The new completion branch does not bypass these checks.
- `markdown.go:36-43`: reply and provenance insertion remain conflict-safe; a replay does not insert another reply row. Completion before delivery remains recoverable because `recoverSavedPlan` still calls `finishAgentPlan`, which renders and queues the view.
- New tests distinguish completed assessed, completed deferred, redacted, foreign-owner, wrong-kind and wrong-update cases; forbidden attachment/effect/assessment POSTs are observable. An interrupted attachment produces no completion marker. The database failure test verifies that a failed marker read is not mistaken for absence.
- `integration/saved_knowledge_attachment_recovery_test.go` contains real-flow assertions for memo/curate interrupted attachment recovery, one durable reply, no repeated domain/model/assessment work, unchanged quota, unchanged visible replay messages and source/permission/history fences. Those are inspected assertions, not execution evidence from this review.
