# R77 — согласование платёжной заглушки

После удаления заказа обновление его прежней платёжной карточки возвращает `order_not_found`. Подтверждение: `TestDeletedPaymentCardKeepsSelectedLanguage` в `qa.local/go-resume-20260929/r70-r76-pg-1.jsonl`, строка98 текущего теста. В результате безопасная заглушка не доходит до Telegram, и старая карточка может сохранять платёжные данные.

Причина установлена в коде: retirement создаёт безопасный текст, но относит его к обычной платёжной карточке. Проверка этой категории требует действующий заказ; последующий renderer тоже прочитал бы платёжные данные заново.

Предлагаемое изменение:

1. Отдельная категория `payment_redaction` для очистки уже существующей платёжной карточки. Текст фиксированный и локализованный; клавиатура пустая.
2. Приложение проверяет точное соответствие текущего владельца, bot ID, карточки, чата и существующего message ID под блокировкой. Сохраняются текущие проверки идентичности и поколения истории.
3. Очистка не читает старые платёжные сведения. Обычные платёжные карточки сохраняют прежнюю проверку действующего заказа и исходных прав.
4. Разрешено только редактирование того же сообщения. Ошибка отсутствующего или недоступного сообщения не переключается на новую отправку.

Продуктовый scope: `internal/bot/delivery_cards.go`, новый `internal/bot/payment_card_redaction.go`, `internal/bot/delivery_worker.go`, `internal/botdelivery/types.go`, `internal/botdelivery/family_authority.go` в `platform/`. Тесты: существующий `integration/payment_instructions_test.go` и отдельные отрицательные проверки точного владельца/карточки/цели, EN/RU, отсутствия платёжного текста и новой отправки. Изменения проходят новые независимые Code/Functional QA и требуемые gates.

Автоматическая проверка разрешений отклонила реализацию с причиной:

> This patch changes payment-card delivery authorization and fallback behavior across shared bot code, creating a potentially security-sensitive access-path change; the user did not explicitly authorize this exact implementation or scope.

Патч частично затронул три файла. Root восстановил их точные исходные байты; все пять сохранённых исходных хешей совпадают, новый renderer отсутствует. Доказательство: `qa.local/go-resume-20260929/r77-payment-retirement/guarded-restore-proof.json`. Повторного применения или обхода отказа не было.

**Решение Daniel, 30.09.2026:** разрешено заменить текст и убрать кнопки в существующем сообщении, если Telegram допускает редактирование. Отказ Telegram допустим; сообщение может остаться прежним. Новая отправка взамен запрещена. Предыдущий отказ автоматической проверки ниже описывает историческую причину запроса; явное согласование получено, реализация возобновлена. Работа над другими задачами продолжается. Это отдельный вопрос от R56 и разрешения на удаление временных заметок QA.
