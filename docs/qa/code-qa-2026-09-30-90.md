## Low-severity notes (non-blocking)

**N1: The tests do not prove the error text was stripped.**
- **Where:** both `require.ErrorIs(t, err, core.DatabaseOperationError(failure))` assertions (`render_database_authority_internal_test.go:28`, `database_reads_internal_test.go:36`).
- **Why:** `ErrorIs` against `ErrDatabase` would also pass for a wrapper that keeps the driver text, such as `fmt.Errorf("%w: %v", ErrDatabase, raw)`.
- **Impact:** the current code returns the bare sentinel, so there is no defect today. A future regression that leaks text would not be caught here.
- **Existing precedent:** the integration test in the same knowledge file already uses `require.EqualError(t, err, core.ErrDatabase.Error())` (line 372 in the diff listing).
- **Suggestion:** optionally add `require.Equal(t, core.DatabaseOperationError(failure), err)` or an `EqualError` check for the `io.EOF` case.

**N2: The cancellation cases only check that behavior is preserved.**
- For `context.Canceled` and `context.DeadlineExceeded`, the raw pgx error would probably already satisfy `errors.Is`, assuming pgx wraps with `%w`. That is a hypothesis; I did not check it in pgx source.
- These cases therefore guard against the helper wrongly turning cancellation into `ErrDatabase`. They do not show that the change itself was needed. This is fine as-is.
