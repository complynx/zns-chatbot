## Finding

**[P2] Reject case aliases before decoding assessment objects.** `platform/internal/sandbox/model_fixture_assessment.go:61` and `:133` use `strictFixtureJSON` to populate structs. The helper's duplicate check records exact key spelling (`model_fixture_http.go:142-146`), but Go's typed JSON decoder matches struct fields without regard to case. Thus a complete otherwise valid installation containing `"result":{"worthwhile":true,"Worthwhile":false,"reason":"synthetic"}` is accepted and installs `false`; reversing the two values installs `true`. Similarly, `"event":"wrong","Event":"expected"` can pass the new assessment request validation and consume the expected fixture. A lone `Worthwhile` also substitutes for the documented required `worthwhile` field. These are distinct JSON keys mapped to the same protocol field, bypassing the promised strict required/unknown/duplicate-field checks and making the programmed verdict order-dependent.

Evidence is static: the fixture token walker compares exact strings; the installed Go standard library explicitly documents case-insensitive struct matching and later-member replacement (`C:/Program Files/Go/src/encoding/json/decode.go:44-52`), and its fallback uses `fields.byFoldedName` at line 702. No reproduction was executed under this read-only review assignment. Validate exact allowed key names and required fields at each assessment object boundary before typed decoding, including incoming assessment requests, and add focused rejection cases for aliases and alias collisions. Preserve existing plan behavior outside the intended scope.
