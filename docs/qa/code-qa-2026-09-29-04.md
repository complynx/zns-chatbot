## Finding

**[P1] Expand opaque provenance before the registration lock prelude.** Location: `platform/internal/derivedmutation/registration_admission.go:29`.

The new call to `lockRegistrationPrelude` replaces `beginSourceMutation`, which previously expanded derived proposal/memory provenance through `readsource.LockEvents`. The replacement helper (`registration.go:21`) sends raw `source.Authorities` to `LockRegistrationMutationEvents`. That function only walks present leaves (`readsource/registration_mutation_locks.go:19`); it does not resolve opaque `DerivedProposal` or `DerivedMemory` references. `LockActors` subsequently expands that evidence and takes actor locks (`readsource/mutation_locks.go:45`), but the inherited registration event was omitted from the initial source/target union. Finally, admission calls `lockSource`, whose proposal validity expansion acquires that inherited event FOR SHARE (`readsource/proposals.go:99`, `readsource/causal.go:72`, `passbooking/queries/authority.sql:2`).

A valid source can therefore contain a derived memory with registration provenance for event B while admitting a booking in event A. Transaction 1 locks A and the actor; transaction 2 locks B FOR NO KEY UPDATE and waits for that actor; transaction 1 then requests B FOR SHARE. This is a deadlock and aborts a valid admission. It also violates the explicit requirement that all source and target event locks precede actor locks. This is a source-based concurrency proof, not an executed reproduction.

Resolve the proposal/memory closure before the prelude locks; use the same expanded evidence for the sorted source/target event union and actor set.
