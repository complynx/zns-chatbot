## Finding

**[P2] `tools/migrate/messages_apply_input.go:184-189, 213-228` — windowed retention still permits the age-only exclusions explicitly forbidden by the approved contract.** `validateMessageRetention` accepts both an absent policy and `retention:"window"`; `resolveMessage` then accepts `excluded/outside_window`. A snapshot containing an ordinary old user request can therefore validate and apply successfully with only a permanent exclusion reference and no conversation event. Reconciliation reports success, while history and administrator request counts omit the old request. This is exercised as successful behavior by `TestMessagesExplicitWindowMatchesLegacy` and `TestMessagesReviewedOmissionsAndWindow`. The original contract requires the full available period and explicitly says not to exclude records solely because of age; the Stage E unreleased-model premise does not require compatibility with intermediate windowed inputs. Require `retention:"all"` for this import, reject bounds and temporal exclusions, and change those tests to rejection cases. Preserve explicitly reviewed owner exclusions and privacy omissions.

## Source conclusions

The regenerated private plan is compared byte-for-byte before apply. Source checksums, canonical identities and duplicate-source rejection come from the existing verified stage reader. Resolution digests bind bot namespace, owner, per-record reviewed clock, provenance and unknown-field dispositions. Database identity checks include the bot-specific Telegram link and the target user's Telegram ID. Unknown roles and invalid source records block conversion.

The generic JSON change rejects invalid UTF-8 and unpaired surrogate escapes before Go can replace them. The added parser tests cover paired surrogates, literal escaped backslashes and intentional U+FFFD. The metadata test adjustment retains a meaningful invalid-metadata case after malformed Unicode becomes a stage failure.

Messages retain one logical user/assistant event. The projection stays within 5,000 UTF-8 bytes, and longer retained text goes into a complete owner-private body. Source time is explicit; no Telegram update ID, charge, shared knowledge or business authority is created. Current schema defaults origin to `original`, and reconciliation checks that origin. Current text retrieval filters by owner and retrieves bounded character slices.

Apply serializes importer sessions, uses one transaction per source row, takes a conversation-table writer lock, checks existing owner history before adding rows, and checks that committed references form an ordered prefix. Event/body/reference/temporary-receipt writes commit together. Existing rows take the reconciliation path without inserts or receipt recreation. Permanent references retain the plan/resolution/source binding after receipt removal. Current runtime deletion clears the body and records a terminal tombstone; candidate reconciliation accepts only the corresponding deleted content state and never restores it.

The CLI routes plan/validate/apply/reconcile to the new functions. Apply/reconcile use a context cancelled on `os.Interrupt`; PostgreSQL operations receive that context. SIGTERM is not registered for graceful cancellation, although process termination is handled as an interruption by the per-row transaction/prefix design. File preparation is synchronous and does not observe cancellation. These are source observations, not signal/restart proof.

No runtime import of the disposable importer module was found in the current platform source/module manifest. Permanent tables remain owned by platform migrations. This supports the intended dependency direction, but does not prove the removal rehearsal.
