## Finding

**P2 — runtime clients retain a prohibited localhost authority.**

`tools/e-rehearsal/probes/removal/main.go:145-178` and
`tools/e-rehearsal/probes/coverage/main.go:154-187` explicitly accept
`host == "localhost"` in runtimeConfig. Both focused tests positively assert
that acceptance (`main_test.go:57-62`), and RUNBOOK.md:186-187 documents it.
The scope requires one explicit `127.0.0.1` endpoint for owner, importer and
probes, with no localhost authority. The standalone runtime clients receive
their own projection and its hash; they do not call the Python frozen-allocation
validator. Consequently, a hash-bound localhost projection and matching URL
pass their preconnection checks, including in the removal client's delete mode.

The custom lookup pins localhost to IPv4 loopback, so this is not an ambient
DNS escape. It remains a concrete public-client contract violation and creates
two different accepted authority rules. The Python frozen allocation correctly
requires 127.0.0.1, but that does not change what the standalone clients admit.
Require 127.0.0.1 in both runtimeConfig implementations and the offline projection
validator, replace the positive localhost cases with preconnection rejection
checks, and align the runbook. Request fresh affected review after the change.
