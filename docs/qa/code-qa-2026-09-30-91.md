## Confirmed supporting-path gap (outside scoped diff)

**[P1] Media file downloads discard a real Core SQL failure marker.** In `platform/internal/appclient/media_client.go:42-46`, `Client.Media` replaces non-200 file responses with an ordinary problem or generic error without using `coreResponseError`. A concrete producer exists: `api/media.go:28-32` performs a second `media.Service.Get` for `/v1/media/{id}/file`; a PostgreSQL failure there reaches `respond` (`api/api.go:156-174`), which emits the database marker and a 500 response. If metadata succeeds and the subsequent file SELECT fails, the caller receives unclassified `media download unavailable`. The new AV guards cannot recover the lost provenance. `refineAV` then returns this ordinary error to the turn fallback, or upload processing retries without the required fatal classification. Route file error responses through the bounded Core error decoder while preserving ordinary media absence behavior, and cover successful metadata followed by marked file failure. This is not introduced by the scoped diff, but directly limits AUD23 completion for the reviewed media call chains.

## Tests and limitations

- The two requested test files cover marked versus unmarked domain-shaped failures, joined cancellation classification, no-refusal early return, and preservation of actual saved-plan/media rows when a synthetic classified failure is injected.
- Names containing `SQL` do not mean an actual SQL operation was failed. `TestMediaExecutionSQLDoesNotTerminalize` injects `core.DatabaseFailure(denial)` against a live database; the saved receipt test has no database; the archive test supplies an HTTP marker from a fake server while checking a live saved row. These are valid fallback and persistence checks, not real SQL producer or Bot.Run fault-injection proof.
- A valid marked 4xx with a nonempty problem code is supported by `appclient/client.go:139-156`. This does not establish that real SQL failures produce the tested `media_not_found`, `forbidden`, `history_stale`, or stale-settings shapes. For example, media absence is an ordinary ErrNoRows conversion, whereas a concrete PostgreSQL failure normally becomes marked 500 through `api.respond`.
