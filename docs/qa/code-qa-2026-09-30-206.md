## Finding

**[P2] Preserve cancellation when a missing-payment problem is also present.** `qa.local/go-resume-20260929/c-registration-home-read-20260930/final/platform/internal/interaction/registration_home_reads.go:84-87` checks SQL provenance before finding the missing-payment problem, but does not check cancellation. For `errors.Join(&core.ProblemError{Status: 404, Code: "pass_payment_missing"}, context.Canceled)` (likewise `context.DeadlineExceeded`), `core.IsDatabaseFailure` is false and `errors.AsType` finds the 404. The helper returns `Absent: true` with no error. The manual historical menu displays absence; the agent reader completes a successful historical booking projection after a failed payment read. This violates the requested cancellation/absence distinction and failed-read non-admission condition.

Preserve `errors.Is(err, context.Canceled)` and `errors.Is(err, context.DeadlineExceeded)` before interpreting a problem as absence. Also preserve these errors before the general client-problem fallback in candidate `registration_reads.go:266-271`; otherwise returning the joined error from the helper still lets the agent complete an `unavailable` read. Add joined tagged-404/cancellation and tagged-404/deadline cases at both the helper and full `RegistrationReader.Read` boundary. Require an error, zero helper projection, no completed read, and retention of the consumed reservation. Existing tests cover bare cancellation and SQL-marked 404, but not these combined error shapes. The finding follows from inspected error handling; no test was executed.
