## Findings

### P2 — progress header can make a previously valid result page undeliverable

`platform/internal/bot/admin_message_page.go:46` prepends the progress text to the recipient page. Lines 101–110 still enqueue that entire text as one Telegram message before the chunked view at line 118. `botdelivery/results.go:161` calls `telegram.PrepareSend`, which rejects messages over 4096 UTF-16 units.

Concrete catalog-based reproduction in Russian: 20 destinations `@` followed by 30 `a` characters and a distinct two-digit suffix (33-character valid aliases); thread `9223372036854775807`; state `cancelled`; Telegram message ID 0; saved failure consisting of 100 ASCII `x` characters. The destinations pass the existing destination syntax and nonnegative thread validation, and the failure length is allowed by delivery. The previous recipient-page text is 3823 UTF-16 units. With the truthful new header (Cancelled=20, other counters=0), it is 4100 units. Thus `PrepareSend` fails before the later chunking code can execute. This is a new regression introduced by the extra header, even though the general unsplit-page mechanism predates this patch.

Keep the summary/navigation payload within the Telegram limit or split page text before enqueuing it, preserving recipient navigation and full reviewed content. Add a composed-page boundary check in both locales; the new helper-only translation test cannot catch this path.

### P2 — safe result pages still fail for unknown, parked, and paused recipients

Affected-scope inherited gap, not introduced by the counter SQL: `platform/internal/bot/admin_message_page.go:208` translates each recipient using `admin_message.state.` plus the durable state. Neither English nor Russian registers `admin_message.state.unknown`, `.parked`, or `.paused`. The only registered item states are pending, sending, sent, failed, and cancelled. `orders_locale.go:20` records the translation error; `admin_message_page.go:95–96` returns it before publication. Therefore any page containing one of these durable states cannot show its new whole-job progress, in either locale.

The new integration fixture explicitly creates these states and verifies the service review, but does not compose the bot page. The bot test only translates the progress helper. Add the missing catalog entries and a complete page-render check for all supported durable outcomes before claiming the safe EN/RU result-page requirement is met.
