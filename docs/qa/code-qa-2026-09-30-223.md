a narrow typed capability reader. Each invocation passes the caller's context
and owner to the existing live `PassToolCapabilities` route. Capability failures
return no entries. The host owns action-union projection, descriptors, schema
and ordering. Bot supplies the existing preparation and execution functions;
the host has no import of Bot or Telegram transport.

produce the same sorted tool names. The special discovery rule for

The new adapter delegates to this catalog with exactly the existing callback

## Security, admission, cancellation and receipts

The unchanged host registry refreshes capabilities for list/help/resolve and
intersects them with the admitted VM name scope. New grants cannot enlarge an
existing VM; revoked names disappear. Unknown or unavailable names retain the
generic denial path. The registration capability projection remains a discovery
union, not event execution authority.

The appclient local route still authenticates the requested owner per operation
before calling the domain reader; the separate HTTP route remains available.
The extraction forwards context without replacing or detaching it, preserving
existing cancellation propagation. No new transaction, goroutine, background
cache or capability snapshot is introduced.

The unchanged dispatch path resolves current admission, admits source, prepares,
durably admits the call, executes, bounds/redacts output and completes the saved
call. Registration preparation, exact event authorization, immutable saved
request, source binding, replay key and canonical receipt handling remain the
same callback paths. Domain writes and receipt observation are unchanged; this
catalog move neither grants event-B rights from event-A discovery nor removes
current authorization before execution/replay.

## Test source assessment and limitations

The four new test functions cover ordinary/assignment/cancellation/review/export
and unknown capability projections, sorted names and limits, schema authority
exclusion and batch bounds, live list/help/resolve revocation and immutable VM
scope, owner/update callback forwarding, propagated event refusal, and database
failure without a projection. Parallel tests use independent mutable fixtures;
callback assertions execute synchronously in the test goroutine.

These are source assertions, not executed results. They use a fake capability
reader and callbacks and do not independently prove real event A/B authorization,
SQL cancellation, durable recovery or Telegram behavior. The schema test checks
shape and selected fields rather than exact before/final descriptor equality;
the full descriptor equivalence assessment above comes from direct static
comparison. Required focused tests, pinned lint/build and affected independent
Functional QA remain necessary on the integrated candidate.

performed. No dependency versions, suppressions or gate thresholds changed.
