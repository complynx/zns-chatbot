## Findings

1. **P1 — validate the effective importer connection target.** `tools/e-rehearsal/rehearse.py:106-110` checks only the URL authority/path, then passes the original environment DSN to the importer at lines 253-256. For example, `postgres://postgres@127.0.0.1:58421/synthetic_qa_zns_guard?host=remote.invalid&port=5432&dbname=production` satisfies these URL checks. Pinned pgx v5.11.0 processes URI query settings after authority/path settings and overwrites them (`pgconn/parse_url.go:281`). Its effective target is consequently different. The ownership guard uses Compose psql against the allocated database, so it does not guard the connection the importer actually uses. Reject connection-target overrides, service indirection and alternate hosts, or validate a canonical effective pgx configuration before any connection and execute that same configuration. Add a focused test for query overrides and unsupported targets.

2. **P2 — complete hash preflight before opening the database.** `tools/e-rehearsal/rehearse.py:240-250` calls `guard()` and ledger SQL before checking exported/staged input, plan/resolution and binary hashes. A changed plan, stage, source inventory, migration file or importer binary therefore opens the database before rejection, contrary to the requested boundary. Allocation checks inventory-file digest references but does not validate these actual inputs. Move the complete provenance/archive/binary validation ahead of the first SQL/DB command; apply the same boundary to the other relevant owner actions. Tests should corrupt each bound input and assert no executor/database operation occurs.

3. **P2 — use the food CLI replay contract instead of defaulting missing counters to zero.** `tools/e-rehearsal/rehearse.py:260` uses `summary.get("applied", 0)` for all seven domains. `tools/migrate/food_apply.go:10-16` emits `events`, `reused` and `reconciled`, with no `applied` field. A food replay that performs a new import (`reused:false`) is therefore accepted as zero mutations. Require `reused:true` for food replay, require actual counters for the other six domains, and/or compare permanent state across each replay. Do not treat an absent evidence field as proof of zero changes.
