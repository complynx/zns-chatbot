## Findings

1. **[P1] Reject configured non-Linux clocks before opening the runtime database.** `platform/cmd/zns/main.go:49` only rejects api/bot, while `platform/cmd/zns/registration_fixture_clock.go:73` rejects unsupported platforms inside runApp. Actual startup calls runCommand -> openRuntimeDatabase (`main.go:91`) -> store.OpenNamed -> `p.Ping(ctx)` (`platform/internal/store/store.go:42`) and may enter runtime admission before runApp. Thus a configured Windows app accesses its configured database before rejecting the platform; an unavailable database masks the required Linux error. The helper-only nil-DB test does not exercise this startup route. Move enabled-clock platform/configuration preflight ahead of database opening, retaining post-open allocation/identity checks. Verify the real entrypoint with a database opener that must never be called for a configured non-Linux clock.

2. **[P2] Refresh application capture time after the ingress allocator lock.** `platform/internal/passbooking/admission.go:136` samples time before `admissionPosition` at line 154, which reaches the allocator lock in `platform/internal/registrationingress/ingress.go:94`. ApplicationPosition correctly samples received_at after that lock, but insertAdmission receives the earlier sample at `admission.go:166`, using it for checked_at and the application turn deadline (`admission.go:212-213`). An advance during the lock wait can create a new application whose checked_at predates its reception and whose turn has already expired. An independent offline overlay test executed the candidate captureNewAdmission with a mock transaction advancing the trusted clock during allocator-lock acquisition. Output: `received=2026-10-01T12:11:00Z checked=2026-10-01T12:00:00Z expiry=2026-10-01T12:10:00Z`; the freshness assertion failed. Sales-open/event-finish decisions also retain the earlier observation. Refresh the configured capture observation and its decisions after allocator acquisition, use the actual new ingress reception for application retention, and preserve the nil-clock production observation/query behavior. Cover a clock advance across both retention and sales/event boundaries during the lock wait.

3. **[P2] Enforce exactly the eight case-sensitive state fields without duplicates.** `platform/internal/registrationclock/state.go:77-79` decodes directly into a struct with DisallowUnknownFields. This does not reject duplicate keys or case-insensitive matches. An independent offline executable using an unchanged copy of candidate state.go passed Decode plus Validate for both `"version":0,"version":1` (nine JSON entries) and `"VERSION":1` in an otherwise valid state. Both printed `accepted=true version=1`. These malformed publications violate the strict eight-field contract and hide a wrong version behind a duplicate. Check exact allowed key spelling, presence, count and uniqueness before decoding the values; keep the existing size/trailing-content checks. Add duplicate-key and wrong-case rejection cases.
