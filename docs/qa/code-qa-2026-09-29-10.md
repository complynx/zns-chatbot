## Finding

- **P2 — queued retry behavior is not exercised.** `platform/integration/pass_redaction_delivery_test.go:78-138` tests first-attempt success, pre-send revision cancellation and a terminal missing-target response. None defers a redaction attempt and dispatches it again. `platform/integration/bot_delivery_fixture_test.go:24-26,54-55` explicitly leaves failed attempts for explicit tests, so calling the pump once does not prove retries. This matters because `platform/internal/botdelivery/admission.go:180-181,223-225` changes target handling after the first attempt and `platform/internal/bot/delivery_worker.go:93-95` uses the persisted target when editing. Add a real queued retry case: return a retryable response on the first edit, prove the deferred attempt, make that same intent eligible and dispatch it again, then assert its attempt count, canonical target, fixed notice and zero sends. Include missing target on the second attempt to prove no fallback during retry. This is missing evidence, not a reproduced product defect.
