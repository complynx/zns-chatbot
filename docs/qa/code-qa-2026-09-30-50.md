## Finding

### P2 — cancellation exit discards the current SQL failure

`platform/internal/passbooking/deadlines.go:47-49` checks `ctx.Err()` before adding `processErr` to the aggregate. If an event returns a sanitized SQL failure and the context is canceled by the time this check runs, the returned error contains earlier failures and cancellation but omits this event's SQL provenance. With no earlier SQL failure, `errors.Is(result, core.ErrDatabase)` becomes false. A preceding domain failure does not change this outcome. The stated requirement that any encountered SQL fault remain identifiable is therefore incomplete on this exit.

This can occur when cancellation races with a completed failing SQL operation. A deterministic focused regression can use an intake resolver that encounters/returns a sanitized database failure while canceling the context before returning; `processEventDeadlines` forwards that error at lines 87-89. Preserve `processErr` in the cancellation return as well as prior failures and context cancellation. The existing cancellation branch predates this patch, but is still a relevant exit of the aggregate-preservation change.
