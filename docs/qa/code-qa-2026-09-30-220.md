## Static findings

### Cache safety and concurrency

`CacheObservations` obtains both cache mutexes with `TryLock`, releases the first if the second is unavailable, and returns unavailable rather than waiting for provider work. Both maps are read under their owner locks; concurrent scrapes retain no mutable collector snapshot. Traversal is bounded by the existing 1024-entry-and-flight cache limit. The observation method neither renews deadlines nor evicts entries, creates flights, invokes the provider or modifies invalidation generations.

Usable versus expired counts use one current instant and the same strict `now.Before(until)` condition as cache authorization. Retired flights remain counted until their existing provider worker completes. Existing exchange/verification lifetime caps, fixed cache deadlines, subject invalidation and stale in-flight rejection remain unchanged. No new lock inversion or goroutine ownership is introduced.

### Truthful export and bounded labels

Successful scrapes expose nine fixed series per adapter role: availability, two states for each of two caches, flights and capacity. Registration accepts only `api` and `bot`; cache and state labels are literal finite vocabularies. Credentials, token hashes, subjects, URLs and error strings cannot enter labels or exported metrics.

Unavailable, cancelled, contended or invalid observations emit only `snapshot_available=0`. Entries/flights/capacity are omitted, so the collector neither republishes an old in-process snapshot nor fabricates empty cache gauges. Validation rejects negative counts and impossible capacity totals before metric creation. The concrete reader is bounded and cancellation-aware; the two-second context is additional protection, not a claim that context can interrupt an arbitrary injected callback.

The existing per-runtime registry receives collectors through error-returning Register. Duplicate same-role registration fails; different fixed roles coexist. Descriptor label names/help remain consistent. No global registry, new dependency or lint suppression is added.

### Construction and existing model accounting

The frozen app/API bindings observe the exact already-created authoritative API adapter. Bot configuration observes the adapter assigned to exchange and local links after bot identity verification. App and standalone-bot paths set the Runtime observer before bot authentication configuration. Sandbox authentication yields no adapter and therefore registers no identity-cache collector. Nil telemetry follows existing caller checks. Construction, identity links, invalidation hooks and authentication behavior otherwise remain unchanged.

Current credit usage preserves unknown counters through nil values and unknown basis; the provider path captures reported numeric receipts and settles dispatched attempts. This candidate does not alter or complete that model accounting/observability mechanism. No model-usage acceptance is inferred from this cache slice.

### Tests and worker assertions

The supplied tests cover observation retention, no deadline renewal, expiration counts, retired flights, committed invalidation visibility, both contention paths, cancellation/recovery, nil adapter, role rejection, duplicate registration, exact cardinality, invalid totals, failed-scrape omission and recovery.
