## Blocking finding

**[P2] Keep separate persisted-source budgets during current/prior lock discovery** — `platform/internal/botdelivery/pass_receipt_retirement.go:349` (also line 354; called at `admission.go:126`).

`passPreparationLocks` merges current authority evidence and the prior successful receipt's authority evidence using `readsource.Merge`. That helper validates the combined result against the single persisted-record budget (256 authorities, including causal leaves, and 1 MiB). The current and prior records are independent valid records. For example, 129 distinct valid `ReadOwnerMenu` leaves in each record produce a 258-leaf union and `source_authority_limit`, even though both references were individually valid and successfully persisted. A history reset can likewise leave a near-limit denied prior record alongside a small valid new source.

This newly affects normal admission and receipt continuation whenever an old actual target is discovered. The error occurs before the source denial is evaluated, so `failPassAdmission` cannot retire the revoked old target; retries repeat the same immutable union failure. After a successful fallback send, `ApplyReceipt` can also remain unfinished with the private target and callbacks retained. Previously each payload could be validated within its own budget. This violates delivery preservation and complete retirement/retry handling.

Build a lock-discovery window from individually validated records without applying a new aggregate persisted-record budget. Preserve canonical combined event/actor lock order, then validate each payload independently. The existing `readsource.LockRegistrationMutationPrelude` documents this per-record/window distinction. Add an offline boundary case and real PostgreSQL admission/receipt retirement cases with individually valid disjoint records whose union exceeds 256; do not raise persisted limits or drop evidence.

Evidence is direct source analysis: `readsource/capture.go:13` validates every input and the final union; `readsource/authority.go:43` counts causal leaves and enforces the final budget; `passbooking/read_authority_types.go:9` sets 256. No database reproduction was run under the stand restrictions.
