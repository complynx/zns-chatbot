## Findings

1. **P2 — callback_receipts.go:110–114: artificial EOF admits malformed oversized requests as matched evidence.** `io.LimitReader` hides the remaining request after 4097 bytes. A valid callback JSON object followed by more than 4097 whitespace bytes and `!` is malformed JSON, but the second Decode reaches artificial EOF and sets `valid=true`. The independently executed probe produced one successful matched receipt. This violates the documented malformed-request evidence condition and makes the apparent 4096-byte admission bound incomplete. Read at most limit+1 bytes and explicitly reject observation when the original payload exceeds the limit; only parse a proven complete bounded body. Keep the existing Bot API result policy. Add a whitespace-padded oversized/malformed suffix case.

2. **P2 — fake.go:244–245: response publication precedes callback binding, so a genuine fast ACK can be lost permanently.** The full getUpdates response is passed to ResponseWriter before `observeDeliveredCallbacks` installs bindings. Response bytes can become available to the caller before Write/Encode returns. A caller can answer immediately; `observeCallbackResponse` finds no binding and discards the observation. A deterministic response-writer probe exposed the batch bytes and performed the authenticated answer call before the write returned; readback remained empty even after getUpdates completed. Mutex protection does not establish publication order. Make successful batch publication and binding admission ordered so an ACK for published callback bytes cannot outrun registration, while retaining the documented response-generation boundary and unchanged provider response policy. Add a deterministic early-answer case.
