# R56: предложение чтения результата завершённой операции

**Решение Daniel получено 30.09.2026:** «Да, по уже отменённой регистрации попытка возобновления конечно должна возвратить \"регистрация отменена\"». Ограничения владельца, актуальных прав и подтверждённой завершённой операции ниже сохраняются. Новый кандидат готовится отдельно; код ещё не принят. Описанные далее ожидание подтверждения и отклонённый частичный патч относятся к истории предложения.

**Статус: неполное предложение, сейчас не применено. Частично применённые изменения восстановлены root.** [Сохранённый отклонённый патч](../../qa.local/go-resume-20260929/r56-proposed-change.patch) — точный частичный кандидат в формате apply_patch, не готовая реализация. В нём ещё нет метода ObserveReceipt, обработки полномочий результата, удаления служебных полей из ответа и тестов. Его нельзя применять как завершённое исправление. [Полный инженерный дизайн](../../qa.local/go-resume-20260929/owner-resume-r56-design.md) описывает оставшуюся работу.

Сейчас пользователь отправляет приглашение, операция успешно завершается. Позже он отменяет свою регистрацию. При чтении истории старый ответ теряет актуальность и скрывается; исходный сценарий становится недействующим. Попытка «возобновить мою операцию» затем завершается ошибкой, хотя приглашение уже было выполнено.

Предлагается для такого **собственного завершённого приглашения** разрешить отдельное чтение: по прежнему идентификатору операции вернуть текущее состояние своей регистрации — в этом примере «отменена». Приглашение повторно не выполняется; число бизнес-операций остаётся два. Это новый запрос к текущим данным, а не восстановление старого ответа или исполнения.

Обязательные ограничения:

- Точное завершение подтверждается канонической квитанцией и совпадающим идентификатором запроса, а не флагом в старом результате сценария.
- Владелец и действующие права проверяются заново; проверка квитанции и чтение регистрации происходят в одной защищённой транзакции. Чужой идентификатор и отозванные права не дают доступа.
- Недействующий сценарий, старый источник и история остаются скрытыми. Старый текст, результат и служебные ключи не возвращаются; выполнение исходной команды не возобновляется.
- Незавершённая операция, отсутствующая или поддельная квитанция не допускают ни чтения через этот путь, ни повторного исполнения. Пакетные, административные и экспортные операции в первый этап не входят.
- Новый ответ получает актуальные ограничения чтения; последующее изменение данных или прав снова делает его недействительным.

Подтверждение требуется именно для этого изменения поведения: **разрешить такое отдельное чтение текущей своей регистрации по подтверждённой завершённой операции после прекращения действия исходного сценария, сохранив перечисленные ограничения**. Подтверждение не означает приёмку кода: после реализации нужны тесты, независимые Code QA и Functional QA.

Автоматическая проверка разрешений отклонила первую попытку применить патч. Её причина дословно:

> This broad patch changes retired-operation resume into a new receipt-based current-booking read, potentially exposing private booking data and altering authorization/privacy boundaries; the trusted user messages do not explicitly authorize this exact behavior or its seven-file implementation.

Проверка указала на возможное раскрытие приватных данных регистрации и изменение границ доступа без явного разрешения пользователя. Обхода отказа не было. Однако отказ инструмента оказался неатомарным: до него применились изменения в `agenthost/script_types.go` и `bot/script_pass.go`; остальные изменения кандидата не применились. Первоначальное сообщение агента «продуктовые файлы не изменены» было ошибочным. Root сверил точные различия и хеши с сохранёнными исходниками, сохранил частично изменённые версии и восстановил только эти два файла точными исходными байтами. Проверка root подтвердила, что параллельные изменения R57 не затронуты. Сведения проверки сохранены в `qa.local/go-resume-20260929/r56-partial-application-inventory.json`. Тесты агент не менял и не запускал. Параллельная проверка root выявила ошибку компиляции из-за незавершённого применения. Патч здесь сохранён только для рассмотрения; он не готов к применению.
