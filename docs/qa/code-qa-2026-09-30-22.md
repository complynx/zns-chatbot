## Findings

1. P2 — `platform/internal/agenthost/script_registration_completion.go:220`: rebase `PassContext.QueueAuthorities` for the exact payment transition. The loop changes only `dependency.Booking`. A script reserved after an earlier `passes.payments.review` has the pending review authority in `PassContext.QueueAuthorities` (`ScriptPassContext`, `evidence_authority.go`; captured by `script_store.go:206`). After accept/reject commits, `authorizeRegistrationTransition` calls `AccessChanged`; `dependenciesChanged` calls `RegistrationContextChanged` for every dependency, and `bot/script_pass_context.go:24-31` validates those unchanged queue authorities. Their version/attempt is now stale, so the successful mutation loses its minimal completion receipt. This is the ordinary two-step review-then-decision flow, unlike the new tests that perform both inside one newly reserved script. Rebase only the matching authority in the detached validation copy and preserve all other source checks. Add a two-run integration case for accept and reject.

2. P2 — `platform/internal/agenthost/script_registration_completion.go:463`: probe the canonical payment receipt for an admitted payment call with an uncertain response, before normal source retirement. When the domain commits but the HTTP response is lost, `bot/script_pass_execute.go:50-56` returns `complete=false, interrupted=true`; `CommittedPassReceipt` is false and this guard bypasses `PassPaymentReceipt`. `CompleteCall` then takes the normal `updateLedger` path, whose pre-change authorization sees the already-invalid pending review source and retires the record. The new exact receipt exists but is never consumed; `ReadRegistrationOperation` refuses retired admissions (`registration_operations.go:122-125`), and `ScriptHost` recovery only probes knowledge calls. The payment remains committed and is not duplicated, but the requested exact minimal completion cannot be recovered. Probe without re-executing, preserve ACL/incarnation/causal fences, and test a transport that dispatches the payment successfully then drops its reply.
