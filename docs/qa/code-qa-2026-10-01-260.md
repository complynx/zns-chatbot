## Findings

### P1 — preparation commands inherit worker secrets without worker URLs

`prerequisites.compose.yaml:12-18` makes every tool inherit `app.env` and
`runtime.yaml`. `clock-control.md:77` requires that environment file to contain
`MEDIA_WORKER_SECRET` and `STICKER_WORKER_SECRET`. The managed app needs nonempty
values because `runtime.compose.yaml:47-48` enables both worker URLs. However,
`migrate`, `fixtures`, `registration-init` and `registration-read` do not set
either worker URL, and `runtime.yaml` has neither URL.

The existing config loader maps these secret variables into worker settings
(`platform/internal/config/environment.go`). `Config.Validate` invokes
`validateValues` for maintenance commands too. At
`platform/internal/config/validate.go:137-142` it validates both workers;
`validWorker`, at lines 220-227, rejects any nonempty secret without an HTTP
origin. `platform/cmd/zns/main.go` loads and validates config before opening the
database. Consequently the documented first migration exits with
`configuration media requires an HTTP origin and a nonempty single-line secret`.
Removing both secrets from the shared file instead makes the managed app fail.
Thus the declared configuration cannot satisfy both phases.

Supply valid worker URL/secret pairs to preparation commands, or omit worker
settings from those commands using a distinct narrowly scoped environment/config.
Keep the managed app's required settings and all clock exclusions intact. Verify
the actual resolved nonsecret config for every ordinary preparation/read command
before accepting the corrected templates. This finding is established by the
immutable source wiring and validation path; no private envfile was read and no
database or product process was started.

### P2 — coordinator receives a prohibited clock activation variable

`owner.compose.yaml:22` sets `REGISTRATION_CLOCK_ANCHOR` in the coordinator's
environment. The original contract permits the five `REGISTRATION_CLOCK_*`
variables only in the combined app and bounded transient operator CLI, explicitly
excluding the coordinator. Having no clock mount does not satisfy that environment
restriction. The anchor is nonsecret, but this is still a contract violation in
the owner template.

Provide nested Compose's interpolation input through a preparation setting that
is outside the clock activation namespace, or freeze that value into the reviewed
nested composition. Only the app/operator process environments should receive
`REGISTRATION_CLOCK_ANCHOR`. Check the resolved owner environment and preserve the
same immutable anchor for app and operator after the correction.
